# `.env` と `.env.example` の役割

APIキーのような「人に見せられない値」を、どう扱っているかの説明です。

## ひとことで言うと

| | `.env` | `.env.example` |
|---|---|---|
| 中身 | **本物のキー** | 記入見本（値は空） |
| 置き場所 | 自分のPCの中だけ | プロジェクトと一緒に配る |
| Gitに上げる | **絶対に上げない** | 上げる |
| プログラムが読む | **読む** | **読まない** |
| 無いとどうなる | アプリが動かない | 人が設定方法を知る手段を失う |

## なぜ2つ必要なのか

`.env` はGitに上げられません。キーが入っているからです。

でも上げないと、**次に困る人**が出てきます。

- 別のPCでこのアプリを動かしたくなった半年後の自分
- このフォルダを渡された誰か

その人は「何という名前の項目に、何を書けばいいのか」を知る手段がありません。
コードを全部読めば分かりますが、それは酷な話です。

そこで、**値だけを抜いた見本**を一緒に配ります。それが `.env.example` です。

> 鍵そのものは渡せない。でも「どの鍵穴に、どんな鍵が要るか」は教えられる。

## プログラムから見た違い（ここが肝）

**`.env.example` は、プログラムから一度も読まれていません。** 人が見るためだけのファイルです。

```
core/config.py の env_value()
        │
        │ 呼ばれるたびに読む
        ▼
      .env  ──→  GEMINI_API_KEY の値を取り出す ──→ Gemini API へ
    （本物）

      .env.example       （誰も読まない。人が目で見てコピーするだけ）
```

このため:

- `.env.example` を書き換えても、**アプリの動きは1ミリも変わりません**
- `.env` を書き換えると、**ブラウザを再読み込みするだけで反映されます**
  （起動し直す必要はありません。`core/config.py` が毎回読み直しているため）

## 実際の中身

**`.env.example`**（Gitに入る。これはそのまま公開してよい）

```
# Google AI Studio (https://aistudio.google.com/apikey) で取得したAPIキー
GEMINI_API_KEY=ここにAPIキーを貼り付け
```

**`.env`**（自分のPCだけ。中身は人に見せない）

```
GEMINI_API_KEY=（取得した50文字ほどのキーをそのまま貼る）
```

項目名（`GEMINI_API_KEY`）は同じで、**値だけが違う**。これが2つのファイルの関係です。

## 新しいPCで動かすときの手順

1. `.env.example` を**複製**する（移動ではなく、コピー）
2. 複製したファイルの名前を `.env` に変える
3. `=` の右側に、自分のキーを貼り付けて保存
4. アプリを起動する

`.env.example` は残したままにします。次にまた必要になるので。

## やりがちな間違い

**① ファイル名が `.env.txt` になっている**

Windowsは拡張子を隠すので、メモ帳で保存すると勝手に `.txt` が付きます。
アプリからは「`.env` が無い」ように見えて、キー未設定の扱いになります。

**② `.env.example` のほうに本物のキーを書いてしまう**

**これが一番危険です。**`.env.example` はGitに上がるので、キーが公開されます。
しかも一度コミットすると、あとで消しても履歴に残り続けます。

本物を書く先は、必ず `.env` のほうです。

**③ 値をクォートで囲む**

```
GEMINI_API_KEY="AQ.Axxxx"    ← 余計な " が値の一部として扱われることがある
```

このアプリでは前後の空白と引用符を取り除くようにしてあるので実害は出ませんが、
一般的には囲まないのが無難です。

**④ `.env` を人に送る**

キーを渡すことになります。渡したい相手には `.env.example` を渡し、
キーは本人に取得してもらうのが原則です。

## `.gitignore` との関係

`.gitignore` に `.env` と書いてあるので、Gitに上げようとしても無視されます。

ただし **`.gitignore` が守ってくれるのはGitだけ**です。
フォルダをZIPで固めて渡す、クラウド同期フォルダに置く、画面共有で開く——
これらは素通りします。「Gitという1つの経路だけを塞いだ」が正確な理解です。

## 似た仕組み

同じ考え方は、道具が変わっても出てきます。

| 仕組み | 使われる場所 |
|---|---|
| `.env` / `.env.example` | 多くの言語・フレームワークで共通 |
| `.streamlit/secrets.toml` | Streamlit標準のやり方（このアプリでは使っていない） |
| `.dev.vars` | Cloudflare Workers のローカル用 |

名前が違うだけで、**「本物は手元だけ、見本は配る」**という骨格は同じです。
