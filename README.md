# AIライティングツール

Python + Streamlit で作った、個人用のライティング支援ツールです。
データベースや認証はありません。自分のPCで動かして使います。

## 機能

| 機能 | 用途 |
|---|---|
| ブログ記事 | テーマと読者を指定して、記事の本文または構成案を生成 |
| メール返信 | 受信メールを貼り付け、返信の方向性を選んで返信文を生成 |
| 文章要約 | 長文を6種類の形式（3行／箇条書き／Q&A など）で要約 |
| リライト・校正 | 誤字修正、読みやすく整える、トーン変換、長さ調整 |
| SNS投稿文 | X / Instagram / LinkedIn など媒体別に複数案を生成。**写真を見せると、その写真に合った文章を書きます** |

## 使い方

### 起動する

プロジェクト直下で:

```
.venv\Scripts\streamlit.exe run app.py
```

ブラウザで http://localhost:8501 が開きます。止めるときはターミナルで Ctrl+C。

### 今は「ダミー動作」です

使うAIをまだ決めていないため、生成ボタンを押すと、AIの代わりに
**AIへ送られる予定の指示文**がそのまま返ります。

画面の操作・入力欄・結果の表示・保存は本番と同じなので、この状態で
ひととおり触って確かめられます。プロンプトの中身が見えるので、
「どう書くとAIに何が伝わるか」の練習にもなります。

### 使うAIを決めたら

直すのは2か所だけです。

1. `core/providers/` に、そのAI用のファイルを1つ作る
   （用意するのは `generate_stream()` 関数ひとつ。`stub.py` が見本です）
2. `core/config.py` の次の3つを書き換える
   - `PROVIDER` … 作ったファイル名（例: `"gemini"`）
   - `API_KEY_ENV` … APIキーを書く `.env` の項目名（例: `"GEMINI_API_KEY"`）
   - `MODELS` … 使うモデルの一覧

そのあとAPIキーを設定します。

1. `.env.example` を複製して `.env` という名前にする
2. 該当する行の `#` を外し、`=` の右側にキーを貼り付けて保存する
3. ブラウザを再読み込みする

`.env` は `.gitignore` に入れてあるので、Gitには上がりません。
この2つのファイルの役割の違いは [docs/env-files.md](docs/env-files.md) に書いてあります。
Windowsは拡張子が隠れているため、`.env.txt` になっていないか確認してください。

> モデル名は、記憶や公式の一覧だけを根拠に書かないこと。
> 提供が終了したモデルが一覧に残っていることがあります。
> `check.py` で実際に1回生成を通して、使えたものだけを `MODELS` に書きます。

### うまく動かないとき

```
.venv\Scripts\python.exe check.py
```

Python・ライブラリ・設定・APIキーを順に点検し、実際に1回生成を試して、
「次にすること」を日本語で出します。

### 別のPCで動かす場合

```
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## ファイル構成

```
app.py              起動の入口。ページの一覧をここで登録する
core/
  config.py         使うAIの指定、モデル一覧、既定値、APIキーの読み込み
  menu.py           画面に並べる機能の一覧（機能を増やすときに編集する）
  llm.py            AI呼び出しの窓口＋エラーの型（全機能で共通）
  providers/
    stub.py         ダミーのAI（AIを決めたら削除してよい）
  ui.py             画面の描画（入力フォーム→生成→結果表示）
tools/
  base.py           機能を定義するための型（Field / ToolSpec）
  blog.py           ブログ記事 … 入力欄の定義とプロンプトの組み立て
  email_reply.py    メール返信
  summarize.py      文章要約
  rewrite.py        リライト・校正
  social.py         SNS投稿文
app_pages/
  home.py           ホーム画面
  blog.py 他        各機能の画面（中身は3行。tools/ を呼ぶだけ）
check.py            設定の点検
```

## 機能を1つ増やす手順

1. `tools/` に新しいファイルを作り、`SPEC` という名前で `ToolSpec` を定義する
   （`tools/blog.py` をコピーして中身を書き換えるのが早いです）
2. `app_pages/` に同じ名前のファイルを作る（中身は3行。既存のものをコピーで可）
3. `core/menu.py` の `ITEMS` に1行足す

画面の描き方やAPIの呼び方を書く必要はありません。`core/ui.py` が引き受けます。
上部のメニューとホーム画面のリンクは、どちらも `core/menu.py` の一覧から作られるので、
3の1行を足すだけで両方に出ます。

## 制約

- 生成結果の自動保存はありません（「ファイルに保存」ボタンで都度保存します）
- 画面内の履歴はブラウザを閉じると消えます
- 1人用です。同時利用や外部への公開は想定していません
